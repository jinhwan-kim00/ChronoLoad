디자인 원칙

모니터 구석에 세워둔 채, 고개를 돌려 0.5초 안에 상태를 읽어낼 수 있어야 한다. 이 문서의 모든 결정은 그 한 문장에서 파생된다.

① 모양이 먼저, 숫자는 나중

정보의 1차 채널은 그래프의 형태다. 숫자는 그래프를 확인 사살하는 용도로만 존재한다.

② 차트는 지표 색, 아이콘은 장치 정체

차트·푸터·상태 점은 지표 종류(CPU 시안 … GPU 앰버)를 따른다. 아이콘만은 그 장치가 무엇인가를 말한다 — 제조사(NVIDIA·AMD·Intel), 매체(SSD·HDD), 연결 종류(이더넷·Wi-Fi·VPN). 두 체계를 16px 아이콘 안으로 격리했기에 서로 간섭하지 않는다.

③ 한 화면, 스크롤 없음

탭·페이지·스크롤이 없다. 장치가 늘어난 만큼 세로가 길어지는 대신 접기로 흡수한다.

④ 접어서 집중

지금 보는 워크로드에 상관없는 지표는 28px 스트립으로 접는다. 접혀도 샘플링과 통계는 계속된다.

⑤ 한 순간을 가로질러 본다

차트 위에 커서를 올리면 모든 카드가 같은 시각을 가리킨다. "GPU가 멈춘 그 순간 디스크는 뭘 했나"를 한 동작으로 확인한다.

⑥ 장치 구성은 살아 움직인다v0.4

Wi-Fi를 켜고, eGPU를 꽂고, USB 디스크를 뽑는다. 재시작 없이 카드가 즉시 나타나고 사라진다. 떠난 장치의 통계는 60초간 보관해 다시 붙으면 이어진다.

라이브 목업

실제 렌더링 규칙을 그대로 구현한 시뮬레이션입니다. 구성: NVIDIA 외장 GPU + Intel 내장 GPU + NVMe SSD + SATA HDD + 이더넷 + Wi-Fi.

직접 해보세요
  • Wi-Fi 끄기 · eGPU 연결 → 카드가 실시간으로 사라지고 나타납니다. 새 카드는 3초간 라벨을 보여줍니다.
  • 카드 헤더 클릭 → 접기/펼치기. 공간이 모자라면 우선순위 최저 카드가 자동으로 접힙니다(점선).
  • 차트 위에 커서 → 전 카드에 같은 시각의 스크럽선과 오버레이. GPU에는 온도·전력·클럭, Wi-Fi에는 SSID·신호가 함께 나옵니다.
  • 카드 위에 커서 → 0.25초 뒤 그 장치의 이름이 헤더에 나타납니다. 더 오래 머물면 전체 사양이 툴팁으로 뜹니다.

아이콘 체계

라벨 텍스트를 쓰지 않기로 한 이상, 아이콘이 장치 정체를 전달하는 유일한 상시 채널이다. GPU는 제조사, 디스크는 매체 종류, 네트워크는 연결 종류를 아이콘 자체로 구분한다.

제조사 색은 아이콘에만 쓴다

브랜드 색을 지표 색 체계에 그대로 섞으면 세 곳에서 충돌한다.

충돌문제해소
NVIDIA 그린 ↔ 네트워크 그린같은 화면에 초록 계열 둘네트워크는 차트·푸터·상태 점에만, NVIDIA는 아이콘에만 → 역할이 겹치지 않는다
AMD 레드 ↔ 경고 레드AMD GPU가 항상 경고처럼 보일 위험경고는 절대 아이콘 색으로 표현하지 않는다 — 테두리 글로우 + 해치 패턴만. 아이콘 레드는 언제나 "AMD"를 뜻한다
Intel 블루 ↔ CPU 시안파랑 계열 근접Intel은 진한 블루(#2B7FFF), CPU는 하늘색 시안(#38BDF8). 위치와 글리프 모양이 추가 단서

따라서 차트 선·채움·푸터 숫자·상태 점은 어느 제조사든 앰버다. 제조사 색은 16px 아이콘과 인덱스 배지 안에만 존재한다.

외장 / 내장 구분은 인덱스 배지로

버스 종류(NVMe / SATA / USB)는 아이콘으로 구분하지 않는다 — 16px에서 세 갈래는 구분이 안 되고, "회전 매체인가 아닌가"만큼 중요하지도 않다. 오버레이 텍스트로 제공한다.

네트워크 카드는 종류와 무관하게 전부 그린이다. GPU에서 제조사 색을 도입한 것은 브랜드 색이 널리 알려져 있어 인지 비용이 0에 가깝기 때문이고, "이더넷 색 / Wi-Fi 색" 같은 관습은 존재하지 않는다. 없는 관습을 발명하면 학습 부담만 늘어난다.

상표 관련 — 제조사 로고와 브랜드 색은 각 사의 등록 상표다. 원본 로고 파일을 그대로 쓰지 않고 16px 라인 아이콘 그리드에 맞춰 자체 제작한 단색 추상 글리프를 쓴다. 색도 브랜드 원본(#76B900, #ED1C24, #0068B5)이 아니라 다크/라이트 배경에서 대비 3:1 이상을 확보하도록 조정한 값이다. 공식 로고·색을 그대로 쓰려면 각 사 브랜드 가이드라인의 허용 범위를 별도로 확인해야 한다.

최초 실행 라벨 페이드

"라벨 0개"는 익숙해진 뒤에는 최적이지만 첫 5분은 불친절하다. 최초 1회에 한해 3초간 라벨을 보여주고 사라지게 해서, 학습 비용만 지불하고 상시 화면은 깨끗하게 유지한다.

접힌 카드는 라벨 표시 중 스파크라인을 잠시 감추고 라벨을 보여준다 — 28px 안에 둘 다 넣으면 어느 쪽도 읽히지 않는다. 라벨은 텍스트 예산 밖이다(일시적이고 사용자가 요청했거나 장치 구성이 바뀐 순간이므로).

hover = "이게 뭐였지?"에 대한 즉답v0.4

라벨이 한 번 사라지고 나면 "세 번째 카드가 어느 디스크였지?"를 확인할 방법이 필요하다. 카드에 커서를 올리면 그 카드의 장치 이름이 헤더에 나타난다.

0.25초 지연을 두는 이유 — 카드 사이를 빠르게 지나갈 때 라벨이 연달아 깜빡이면 화면이 소란스러워진다. 접힌 카드에서는 hover 동안 스파크라인 대신 라벨이 보인다.

카드 구성과 높이 분배

GPU·디스크·네트워크가 각각 여러 개가 되면서 "고정 높이 카드를 쌓는다"는 방식은 성립하지 않는다. 가중치 기반 높이 분배 + 자동 접힘으로 처리한다.

첫 실행 창 높이는 장치 구성에서 계산한다v0.4

카드 종류가 9개까지 늘어나면서 "기본 880"이라는 고정값은 의미가 없어졌다. 첫 실행 시 다음으로 계산하고, 이후에는 사용자가 정한 크기를 따른다.

기본 높이 = 76(헤더) + 16(여백) + 갭(카드수−1 × 8)
    + Σ(기본 펼침 카드 × 130 × 가중치) + Σ(기본 접힘 카드 × 28)
  → 상한 = 작업 영역 높이의 85% · 하한 = 최소 창 높이 420

GPU 2 + 디스크 2 + 네트워크 2 구성이면 약 950이 나온다(목업은 960). 장치가 적은 노트북(GPU 1 + 디스크 1 + Wi-Fi 1)이면 560 정도. 화면이 작으면 상한에 걸려 줄고, 부족한 만큼 자동 접힘이 메운다.

하한을 작업 영역에 비례시키지 않는 이유 — 처음에는 "작업 영역의 60~85%"로 잡았는데, 구현 중 테스트에서 걸렸다. 4K 모니터(작업 영역 2160)에서 카드 3개짜리 노트북이 하한 1296px에 걸리면 카드 하나가 400px씩 차지하는 우스운 레이아웃이 된다. 상한만 화면에 비례시키고 하한은 최소 창 높이(420)로 고정한다.

전체 패널의 첫 줄은 언제나 그 장치의 전체 이름이다 — hover로 이름을 확인하려는 동작과 값을 읽으려는 동작이 같은 제스처로 해결된다.

텍스트 예산의 예외 구역 — 상시 화면은 카드당 숫자 5개로 제한하지만, 오버레이는 사용자가 명시적으로 요청했을 때만 나타나므로 정보 밀도를 높게 잡는다. 온도·전력·SSID를 상시 표시하지 않고 여기로 보낸 이유다.

채택하지 않음 — 두 시점을 동시에 고정해 비교하는 A/B 마커는 도입하지 않는다. 단일 화면 원칙과 충돌하고, 구간 비교는 리셋 마커가 이미 담당한다.

네트워크 인터페이스 분리 v0.4

합산 1카드에서 인터페이스별 카드로 바꾼다. 유선과 무선을 동시에 쓰거나, VPN을 경유하거나, 테더링으로 전환하는 상황에서 합산값은 아무것도 설명하지 못한다.

VPN·터널 인터페이스는 카드로 만들지 않는다
터널을 지나는 바이트는 하위 물리 NIC에도 그대로 계상된다. 1GB를 VPN으로 내려받으면 VPN 카드에 1GB, 이더넷 카드에도 1GB가 찍힌다. 같은 트래픽이 두 카드에 나타나면 "지금 회선을 얼마나 쓰고 있나"라는 질문에 틀린 답을 주게 된다.

그래서 터널은 식별해서 제외한다. 실제 회선 사용량은 하위 물리 인터페이스 카드가 정확히 보여주므로 잃는 정보도 없다. VPN 경유 여부 자체가 궁금한 경우를 위해 설정에 "터널 인터페이스 표시"를 두되 기본 off이며, 켜면 해당 카드에 이중 계상 주의가 함께 표시된다.

어떤 인터페이스를 보여줄 것인가

일반적인 Windows 기기에는 Hyper-V, WSL, Bluetooth PAN, 루프백 등 가상 어댑터가 10개 넘게 존재한다. 전부 카드로 만들면 쓸 수 없다.

단계규칙
1. 제외IF_TYPE_SOFTWARE_LOOPBACK, OperStatus != Up
2. 무트래픽 숨김누적 옥텟이 5분간 전혀 변하지 않으면 카드를 숨긴다. 트래픽이 생기면 다시 나타난다 — 이 한 줄이 가상 어댑터 대부분을 걸러낸다
3. 기본 경로 우선GetBestRoute2로 기본 게이트웨이를 가진 인터페이스를 찾아 기본 펼침으로 둔다. 나머지는 접힘
4. 사용자 결정설정에서 인터페이스별 표시/숨김을 고정할 수 있다. 사용자 결정이 2번 규칙보다 우선

표시

  • 디스크·기존 네트워크와 동일한 미러 차트 — 위 = 수신, 아래 = 송신
  • 현재값은 수신 속도, 푸터는 ~ 수신 평균 · ▲ 수신 최대 · ↑ 송신 최대
  • 축 스케일은 인터페이스별로 독립 — 2.5GbE와 Wi-Fi를 같은 축에 올리면 Wi-Fi가 바닥에 붙는다
  • 링크 속도를 아는 인터페이스는 축 상한을 링크 속도로 캡해서 "회선을 얼마나 쓰고 있는가"가 위치로 읽히게 한다

장치 변경 실시간 반영 v0.4

Wi-Fi를 켜고, eGPU를 꽂고, USB 디스크를 뽑는다. 재시작 없이 카드가 즉시 나타나고 사라져야 한다. 목업의 "Wi-Fi 끄기" / "eGPU 연결" 버튼으로 직접 확인할 수 있다.

처리 규칙

디바운스와 레이트 리밋

eGPU를 한 번 꽂으면 WM_DEVICECHANGE가 수십 번 날아온다. 매번 재열거하면 UI가 발작한다.

  • 이벤트 수신 → 300ms 디바운스 후 1회 재열거
  • 재열거는 초당 1회로 제한
  • 연속 3회 실패 시 60초 백오프
  • 재열거는 백그라운드 스레드에서 수행하고, 결과 diff만 UI 스레드에 적용 — 샘플링은 멈추지 않는다
  • 이벤트를 놓쳐도 30초 주기 검증 재열거(어댑터 목록 해시 비교)가 복구한다

왜 "제거"와 "Down"을 구분하는가 — Wi-Fi를 껐다 켜거나 드라이버가 재시작되면 장치가 잠깐 사라졌다 돌아온다. 이때 카드를 지웠다 새로 만들면 리셋 이후 누적 통계가 초기화되어 벤치마크 구간이 통째로 날아간다. 60초 보관 규칙은 이걸 막기 위한 것이다.

사용자에게 어떻게 알리는가

토스트나 알림 배너는 쓰지 않는다 — 텍스트 최소화 원칙에 어긋나고, 구석에 세워둔 위젯이 갑자기 말을 거는 것은 성가시다. 대신 이미 있는 두 장치를 재사용한다.

  • 카드의 등장/소멸 자체가 알림이다 (320ms 페이드 인 + 라벨 3초)
  • 전역 바의 상태 점 개수가 바뀌는 것으로 구성 변화가 보인다

디스크 카드

물리 디스크별 카드 — 합산하지 않는다

디스크를 합산하면 "NVMe가 놀고 있는데 백업용 HDD가 포화됐다" 같은 중요한 상황이 평균에 묻힌다. 장치 특성이 너무 달라(NVMe 7GB/s vs HDD 200MB/s) 같은 축에 올리는 것 자체가 부적절하다.

개수 문제는 기본 접힘과 자동 접힘이 처리한다. 네트워크도 같은 이유로 분리했다(§08).

포화는 처리량이 아니라 활성 시간으로

처리량이 낮아도 디스크는 포화될 수 있다(작은 랜덤 I/O). 활성 시간·큐·응답시간은 차트에 그리지 않고 두 곳에 둔다.

  • 오버레이 — 활성 %, 큐 길이, 평균 응답 ms, 버스 종류
  • 경고 상태 — 활성 시간 95% 이상 3초 지속 → Alert

접근성

  • 대비: 본문 4.5:1, 그래픽 요소 3:1 이상 (다크·라이트 양쪽 검증)
  • 색상 단독 정보 전달 금지 — GPU 전용/공유는 솔리드 vs 해치, 제조사는 색 + 글리프 모양, 어댑터는 인덱스 배지, 디스크·네트워크는 종류 글리프, 지표는 순서 고정
  • 적록색약 사용자에게 NVIDIA 그린과 AMD 레드는 구분이 어려울 수 있다 — 그래서 글리프 모양이 1차 채널, 색은 보조다. 색을 제거해도 정보 손실이 없어야 한다
  • 아이콘만으로 식별이 안 되는 사용자를 위한 탈출구 — L 유지, hover 툴팁, 설정의 "라벨 항상 표시"
  • 키보드: Tab = 리셋 → 카드 순서 → 타이틀바. Space/Enter 접기, 1~9 카드 토글, ←→ 스크럽, Esc 해제
  • 스크린 리더: 축약 없는 전체 문장. 장치 추가·제거는 LiveRegion으로 알린다 — 시각적으로는 카드 등장이 알림이지만 스크린 리더 사용자에게는 보이지 않으므로
  • 접힌 카드도 스크린 리더에서는 전체 값이 읽힌다

스냅샷 창 v1.5

메인 창은 곁눈질용이라 화면이 계속 흐른다. 방금 지나간 스파이크를 붙들어 구간으로 재려면 흐름 자체를 멈춰야 한다. 메인 창 제목 표시줄의 스냅샷 버튼을 누르면 지금 링 버퍼에 있는 것을 통째로 복제해 새 창에 띄운다 — 그 창에는 새 데이터가 들어오지 않는다. 설계는 PROJECT.md §9.6.

스냅샷 버튼은 ⟲ 바로 옆이다

더블클릭이 아니라 버튼인 이유는 둘이다. 더블클릭은 발견되지 않고, 차트 위 더블클릭은 이미 시간 창 전환(60s → 180s → 600s)이 쓰고 있다. 한 제스처에 두 기능을 얹으면 어느 쪽도 확실하지 않다.

⟲ 는 측정 구간의 시작점을 옮기고, 스냅샷은 그 구간을 통째로 떠낸다 — 같은 일의 두 면이라 같은 자리에 둔다

요약은 차트마다 그 머리에 붙인다

장치별 요약 카드를 창 맨 위에 몰아 두는 안도 있었다. 차트가 3개일 때는 그쪽이 깔끔하다. 하지만 GPU 2장·디스크 2개·NIC 2개가 붙으면 차트가 8개가 되고, 스크롤한 순간 숫자와 그림이 갈라진다. 숫자는 그것을 설명하는 그림 옆에 있어야 한다.

요약이 말하는 범위는 선택 구간 > 크롭 구간 > 표시 구간 순으로 좁은 쪽이 이긴다. 지금 무엇을 재고 있는지 헷갈리지 않도록 오른쪽 끝에 범위 배지를 단다.

선택 · 크롭 · 확대는 서로 다른 일이다

동작바뀌는 것바뀌지 않는 것
선택 — 차트 위 드래그요약 띠의 숫자보이는 범위, 내보낼 범위
크롭 — 선택 구간으로분석 도메인 — 요약과 내보내기 범위원본 배열. 경계만 좁히므로 되돌리기·전체로 돌아온다
확대 — Ctrl+휠보이는 범위(가로만)내보낼 범위. 보이는 것이 아니라 정한 것을 낸다
세로 축은 확대하지 않는다. 퍼센트는 0~100 고정, GPU 메모리는 용량 기준(§11)이라 세로로 늘이는 순간 그 규칙이 무너진다. 같은 자리의 같은 높이가 늘 같은 값이어야 한다.

휠메인 창스냅샷 창
맨 휠— (스크롤이 없는 창)세로 스크롤
Shift + 휠창 불투명도 60~100%가로 스크롤
Ctrl + 휠시간 폭 — 30·60·180·600·900초 사다리시간 폭 — 연속 확대 (1× ~ 샘플당 4px)
Ctrl+휠만 두 창에서 같은 뜻이다 — 둘 다 "얼마나 긴 시간을 볼 것인가"다. 나머지 둘은 스크롤이 있는 창과 없는 창의 차이로 갈리므로, 한쪽을 익혀도 다른 쪽에서 헛돌지 않는다.
메인 창은 차트 더블클릭이 표준 60초로 되돌린다. Ctrl+휠로 얼마든지 헤매도 돌아올 문이 하나 있다는 뜻이다. 초안의 60 → 180 → 600 순환은 원하는 곳에 닿으려면 몇 번 눌러야 하는지 세야 했고, 지나치면 한 바퀴를 더 돌아야 했으며, 무엇보다 돌아올 문이 없었다.

통계는 실측 표본만 센다

Slow 티어 지표는 Fast 틱마다 직전 값이 다시 기록된다 — 시간 축을 맞추기 위해 일부러 그렇게 한다. 그 유지값을 통계에 넣으면 표본 수가 주기 비율만큼 부풀고, 편차 0인 반복이 표준편차를 끌어내려 실제보다 안정적으로 보인다. 구간 안에 실측 표본이 하나도 없으면 0 이 아니라 — 로 적는다.

내보내기는 CSV 하나뿐

.xlsx 는 쓰기 라이브러리가 필요하다. 이 프로젝트는 차트 라이브러리조차 쓰지 않는다 — 비교용 표 하나를 위해 그 선을 넘을 이유가 없다. CSV 는 엑셀이 그대로 연다.

항목결정이유
인코딩UTF-8 BOM 포함없으면 엑셀이 한글 헤더를 깨뜨린다
행한 틱 = 한 행모든 지표가 같은 틱 그리드에 기록되므로 리샘플링이 필요 없다
실측 아닌 샘플빈 칸유지값을 채워 내면 엑셀에서 평균을 내는 순간 틀린다
열 이름장치명 / 지표 / 단위여러 파일을 나란히 놓고 비교할 때 열 이름만으로 갈려야 한다
창은 모달리스다. 테스트 A·B 를 나란히 놓고 비교하는 것이 이 기능의 주 용도라 여러 개를 열 수 있어야 한다. 그래서 타이틀이 데이터 시작 시각이다 — 창이 여러 개일 때 무엇이 언제 남긴 것인지는 타이틀에서만 갈린다.

열린 UX 질문

  1. 제조사 글리프의 식별 정확도 검증 — 16px에서 NVIDIA/AMD/Intel이 실제로 구분되는지. 실패하면 배지에 이니셜(N/A/I)을 넣는 안으로 후퇴
  2. VPN 이중 계상을 차트에서도 표현할지 — 예: VPN 카드의 영역을 하위 인터페이스 카드에 옅은 오버레이로 겹쳐 그리기. 정보는 늘지만 복잡도가 크게 는다
  3. 장치가 12개를 넘는 워크스테이션 — 종류별 요약 카드 + 개별 펼치기 모드가 필요할지
